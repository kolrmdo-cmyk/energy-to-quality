# Energy-to-Quality: инженерное решение для проверки

## 1. Что это

Практический протокол и воспроизводимый CLI для обучения нейросети на CPU с целью **минимизировать энергию до достижения целевого качества**.

Метрика: **`Joules_to_Q_min`** — джоули, потраченные до первой эпохи, где `test_acc >= Q_min`.  
Оракул: **Intel RAPL package-0** (`/sys/class/powercap/intel-rapl:0/energy_uj`), не таймер и не программный прокси.

## 2. Что именно подтверждено

### A. Подтверждённый чемпион (MNIST 12k, Q=0.94)

Конфиг: `784-64-10`, float32, обычный backprop, Numba JIT, one-cycle LR, batch 64, 40ep, early stop.

| Split | Повторы | Pass | Медиана `J_to_Q0.94` | IQR |
|---|---:|---:|---:|---:|
| 42 | 5 | 5/5 | 29.57 J | [27.64, 32.47] |
| 123 | 5 | 5/5 | 33.61 J | [32.50, 33.86] |

*Повторы = разные seed обучения на фиксированном split.*

### B. Конфиг для full MNIST (Q=0.95)

Конфиг: `784-128-10`, batch 128, 20ep, one-cycle `max_lr=0.08`, Numba JIT, early stop.  
Стандартный split 60k/10k фиксирован, 5 разных seed обучения: **5/5**, медиана **263.69 J** [198.80, 320.36].

### C. Честное сравнение с baseline (full MNIST, Q=0.95)

Тот же split, модель, batch, epochs, RAPL; режимы чередовались; разные seed обучения на одном split.

| Прогон | Повторы | const_lr 0.03 | one-cycle 0.08 | Парный итог (const−one) |
|---|---:|---|---|---|
| v36 | 5 | 730.69 J [563.69,852.27], 5/5 | 427.13 J [276.11,729.03], 5/5 | one-cycle лучше по медиане, IQR перекрываются |
| v37 | 10 | 765.98 J [722.95,827.68], 10/10 | 656.13 J [636.49,715.80], 10/10 | +103.76 J медиана, 8/10 в пользу one-cycle, 1.17x |
| v37b | 20 | 267.70 J [242.25,592.77], 20/20 | 240.23 J [209.93,433.22], 20/20 | +36.71 J медиана, 13/20 в пользу one-cycle, 1.15x |

**Сводка:** во всех трёх сравнениях one-cycle лучше по медиане/среднему и выигрывает в большинстве пар. Абсолютные джоули зависят от фоновой нагрузки пакета.

## 3. Почему этому можно доверять

- **Честный оракул:** RAPL package-0, не внутренний таймер.
- **Честный протокол:** warmup вне замера, чередование режимов, повторы, медиана+IQR+pass_rate, парное сравнение.
- **Воспроизводимость:** есть скрипты и JSON-артефакты.
- **Отрицательные результаты тоже зафиксированы:** EP/FF/DFA/DRTP/ERB/проверенные data-efficiency стратегии на этом CPU не дали устойчивого выигрыша над clean backprop baseline.

## 4. Границы (честно)

- RAPL package-0 измеряет **энергию всего CPU-пакета**, включая фон системы; абсолютные J плавают.
- Результат подтверждён на **Intel CPU + MNIST/MLP**; автоматического переноса на GPU/TPU/большие модели нет.
- Это **практическое инженерное решение/протокол**, не физический минимум и не «новая теория обучения».

## 5. Что проверять представителю

Проверка не требует доверия к словам — только запуск:

```bash
cd energy-to-quality

# Быстрая проверка чемпиона (full MNIST, 5 повторов)
uv run --with numpy --with scikit-learn --with numba -- \
  python scripts/run_champion.py --task mnist-full --q-min 0.95 --repeats 5 --out results/verify_champion.json

# Честное сравнение baseline vs one-cycle (10 повторов, чередование)
uv run --with numpy --with scikit-learn --with numba -- \
  python scripts/run_proof.py --repeats 10 --out results/verify_proof.json
```

Что смотреть в `verify_proof.json`:
- `summary.const_lr.q0.95` и `summary.onecycle.q0.95` — pass_rate, median_J, IQR;
- `paired.0.95` — парные разницы, сколько раз one-cycle лучше;
- `idle_power_before/after`, `system_before/after` — условия прогона.
